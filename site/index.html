它解决什么问题

Android 上做系统级调整（省电、性能调度、动画调速、隐私开关），传统路径是 Root + Magisk 模块。 但 Root 门槛高、有风险、影响保修。

Root + Magisk

能力最全，但要解锁 Bootloader、刷机，有变砖风险，部分应用还会检测 Root。

门槛高

Shizuku / APatch 类

能拿到 shell 权限，但没有好用的模块生态：脚本散落各处，没有生命周期管理，改坏回不去。

无生态

IWPhone

把「拿权限 + 跑模块 + 兜底回滚」合成一件事：配对后即可安装模块，框架统一管理，写入前自动留底。

免 Root 也有生态

核心能力

不只是「给 App 提权」，而是一套能长期运行、可管理、可回滚的模块运行时。

adb

自持 adb，全程手机内完成

应用内捆绑 adb 二进制，自己配对（mDNS 发现配对端口）、自己连接、固定 5555 端口，并支持开机自启。

mod

模块运行时

启停、冲突检测、沙箱记账、配置页（config.prop）、动作按钮（action.sh）、三类日志分离。

snap

写前快照与一键还原

模块首次写入系统资源前记录原值，还原前先展示「当前值 → 还原值」。卸载模块也不会删快照。

compat

兼容现有模块生态

Magisk / KernelSU / AxManager 式模块可直接安装：自动适配 module.prop、service.sh、 webroot/ 等，并自带 BusyBox。

auto

自动化与工作流

模块包内可带 automation.json，装好即出现在「自动化」页；支持事件触发、状态机与工作流编排。

iwsh

iwsh 终端通道

授权后可在系统终端里使用 shell 能力。凭据不落盘：一次性 nonce 领取、60 秒过期，并记录调用审计。

三步就能用起来

App 内有首次激活向导，按顺序点完即可。

1

配对设备

打开开发者选项 → 无线调试，在通知栏输入配对码。配对端口由 mDNS 自动发现，不用手抄。

2

部署框架

框架包内置在 App 里，一键部署到设备并自动固定 ADB 端口。之后开机自动连上并拉起框架。

3

安装模块

从模块库下载 .iwp，或在 App 内直接打开云模块库安装。安装前会做包内容审计。

能力边界

诚实列出做不到的事，比夸大能力更有用。

可以做到

  • 修改 settings / appops / 系统属性等可写配置
  • 运行 Magisk / KernelSU / AxManager 式模块的脚本层
  • 模块配置界面、动作按钮、日志与快照还原
  • 按事件触发的自动化与工作流

做不到

  • systemless 挂载（免 root 环境没有挂载前阶段）
  • Zygisk / 内核类模块
  • 任何需要 su 的操作
  • 拦截绝对路径调用（如 /system/bin/settings），这类写法也不会有快照

安装时会对模块做兼容性预检并给出判定（预计兼容 / 需要 Root / 无法判断）与原因； 预检是静态扫描，注释里的关键词也会命中，偏保守。
